# 📖 公版书共享翻译计划 (Open Public-Domain Books Translation)

欢迎来到**公版书共享翻译计划**！

本项目致力于系统性地将海外公有领域（Public Domain，如 Standard Ebooks 精选源）中**确认国内尚无正式中译本**的高价值经典名著、文学小说、学术历史著作翻译为高水准的**中英双语对照版本**，并输出为美观专业的双语 EPUB 与 Markdown，全部成果以开源形式回馈社区与广大读者。

> 💡 **核心愿景**：打破语言壁垒，拯救被时光遗忘的经典，通过开源协作与 AI 赋能的标准化工程，让优质世界文化遗产以高质量中英双语形式被更多人阅读与学习。

## 🙋 欢迎认领翻译！如何参与？

本项目包含大量的长篇巨著、短篇故事集、诗歌集和戏剧等，单凭个人力量难以快速推进。**我们强烈推荐并热忱欢迎任何人参与认领翻译！**

无论你是文学爱好者、翻译从业者、英语学习者，还是熟悉大模型提示词工程的 AI 译员，都能在本项目中找到施展才华的书目！

### 认领方式与流程 (Claiming Process)

```
1. 挑选书目/章节 ──> 2. 提 Issue 认领 ──> 3. Fork 仓库与翻译 ──> 4. 本地自动化自检 ──> 5. 提 PR 合并
```

#### 第一步：挑选你感兴趣的书目或章节
1. 打开 **[`Plan.md`](Plan.md)**，在主台账中找到翻译状态为 `⚪ 待译` 或 `🟡 翻译中` 的书目；
2. 点击书目目录进入 `翻译项目/<书名>/`，查看 `项目说明.md`（了解背景风格与篇目清单）和 `translation_queue.csv`（查看每一章的状态 `todo` / `done`）；
3. **认领粒度非常灵活**：
   - 📖 **整本认领**：适合篇幅较短的中篇小说、专著或有充裕时间的译员。
   - 📑 **单篇/分章认领**：文集、短篇故事集、诗集等均可按自然章节独立认领（例如仅认领《格林童话未译篇》中的 1~2 篇故事）。

#### 第二步：提交 Issue 认领锁定
为避免重复翻译与劳动撞车，请在 GitHub 仓库的 **Issues** 中发帖登记认领：
- **标题示例**：`[认领翻译] <书名目录名> - <章节名称或整本>`
- **内容说明**：预计完成周期、认领的篇目清单。
- 我们会在 Issue 中回复确认并打上标签，锁定该任务。

#### 第三步：遵循标准翻译规范（SOP）
每本书在 `翻译项目/<书名>/` 下都有完备的上下文：
- **源文**：位于 `原文/<章节>.md`，纯 Markdown 文本，排版干净。
- **术语硬约束**：翻译时**必须严格遵守**该书目录下的 **`术语表.md`**，保持人名、地名、核心专有名词的统一。
- **提示词参考**：本项目提炼了高度工业化的提示词体系，可直接用于 Claude / GPT / Gemini 等大语言模型辅助翻译：
  - 核心引擎：[`prompts/通用翻译引擎.md`](prompts/通用翻译引擎.md)
  - 领域配置：[`小说文学.md`](prompts/领域配置/小说文学.md) | [`技术文档.md`](prompts/领域配置/技术文档.md) | [`历史古籍.md`](prompts/领域配置/历史古籍.md) | [`学术著作.md`](prompts/领域配置/学术著作.md)
- **双语段落标记契约（极重要）**：
  所有译文存入 `译文/<章节>.zh-CN.md`，必须遵循以下结构：
  ```markdown
  ## Chapter Title / 中文章节标题

  ===Original===
  English paragraph or dialogue here...

  ===Chinese===
  中文翻译段落置于此处...

  ===Original===
  Second paragraph...

  ===Chinese===
  第二段中文翻译...
  ```
  - 原文置于 `===Original===` 块，译文置于 `===Chinese===` 块，**严格一一对应、成对闭合**；
  - 章节标题单行合并：`## English Title / 中文标题`，不拆为两份；
  - 段落内不得破坏换行契约。

#### 第四步：本地自动化质量卡点（0 门槛自测）
翻译完成后，运行仓库内置的自动化校验工具：
```bash
python scripts/check_bilingual.py 翻译项目/<项目名>/译文/<章节>.zh-CN.md
```
若检查通过（退出码为 0），说明双语块对称性、标题规范与契约完全达标！

#### 第五步：提交 Pull Request
1. 将当前项目下的 `translation_queue.csv` 中对应章节的状态从 `todo` 改为 `done`；
2. 提交分支并向主仓库发起 Pull Request；
3. PR 合并后，全库看板将自动同步你的成果与贡献者荣誉！

## 🤝 其他贡献方式

除了翻译正文之外，以下维度的贡献同样极其珍贵：

1. **审校与校对（Review）**：
   - 针对已翻译完成的 346 本书目，进行精读纠错、润色与对齐核查；
   - 详细规则请参阅 **[`3_审核WORKFLOW.md`](3_审核WORKFLOW.md)**。
2. **EPUB 排版与出版打包（Packaging）**：
   - 基于通过审核的双语 Markdown，使用 Pandoc 编译生成标准双语 EPUB 电子书（带精美淡黄译文卡片式排版）；
   - 详细规则请参阅 **[`4_打包WORKFLOW.md`](4_打包WORKFLOW.md)**，工具脚本见 `scripts/bilingual_to_epub.py`。
3. **选品查重与勘误（Sourcing & Correction）**：
   - 若发现待译书目在两岸已存在正式出版的中译本，或发现术语表中的专名有更权威的译法，欢迎随时提交 Issue 讨论！

## 🏗️ 核心四大阶段体系与 SOP 手册

整个翻译工程严格解耦为四个标准化阶段，每个阶段均配有严密的标准操作规范与自动化工具：

| 阶段 | 工作流操作手册 (SOP) | 批量提示词 / 工具 | 核心职责与任务 |
| :--- | :--- | :--- | :--- |
| **阶段一：下载与选品** | **[`1_下载与选品WORKFLOW.md`](1_下载与选品WORKFLOW.md)** | `prompts/批量提示词/1_下载与中译本核查提示词.md` | 全网图书抓取与两岸正规中译本交叉查重分流。 |
| **阶段二：翻译执行** | **[`2_翻译WORKFLOW.md`](2_翻译WORKFLOW.md)** | `prompts/通用翻译引擎.md`<br>`prompts/领域配置/*.md` | 推进 647 本精选书目翻译，执行 9 步双语闭环与术语硬约束。 |
| **阶段三：独立审核** | **[`3_审核WORKFLOW.md`](3_审核WORKFLOW.md)** | `prompts/批量提示词/3_批量审核提示词.md` | 100% 译完后触发只读独立精读审校，按 9 项清单核查产出审核报告。 |
| **阶段四：终校与打包** | **[`4_打包WORKFLOW.md`](4_打包WORKFLOW.md)** | `scripts/bilingual_to_epub.py` | 依据审核报告修复瑕疵，编译生成标准双语对照 EPUB 电子书。 |

│   ├── 通用翻译引擎.md                  # 通用翻译规则层（质量/术语/对照格式/契约）

│   └── 批量提示词/                     # 四大阶段自动化批量执行提示词

│   ├── refresh_progress.py            # 全生命周期看板一键刷新工具
│   ├── check_bilingual.py             # 双语 Markdown 格式契约自动化质检工具
│   ├── check_coverage.py              # 20-gram 覆盖率漏译段落检测工具

└── 翻译项目/                          # 📚 647 本精选图书翻译工程库

        └── 审核报告.md                # 阶段三独立精读审校报告
