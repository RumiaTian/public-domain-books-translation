### 3. 根因定位（非译者失误，在抽取环节）

`scripts/extract_play.py` 是本项目实际使用的抽取器（其输出格式 `**人物名**：台词` 与 `*（动作）*` 与本项目 `原文/*.md` 完全一致）。第 83–100 行 `replace_table`：

```python
tds = re.findall(r'<td[^>]*>(.*?)</td>', row, re.DOTALL)
if len(tds) >= 2:
    ...                                   # 有对白的行
elif line:
    result.append(line)                   # 本意：无人物名的整段舞台说明
```

epub 中纯舞台说明行的标记是 `<td class="first-child"/>`（自闭合）+ `<td class="last-child"><i>…</i></td>`。自闭合 `<td/>` 不匹配 `(.*?)</td>`，故 `tds` 长度恒为 1，`if len(tds)>=2` 与 `elif line`（`line` 在该分支里根本未赋值）**双双不进入 → 整行被静默丢弃**。多 `<p>` 的舞台说明块同因被整块丢弃。这也解释了为何：
- `原文/costumes.md`、`原文/characters.md`、`原文/authors-preface.md` 缺失 0 段（不走这条 table 路径）；
- `Scene.` 段（`<p>` 独立于 table）被完整保留；
- 行内 `*（动作）*`（同一 `<td>` 内的 `<i>`）被完整保留；
- 每幕收场的 `Curtain.` 行一并消失。

对照工具 `scripts/epub_to_md.py` 的 `_render_table()` 对同一结构处理是**正确的**（persona 为空时 `lines.append(prefix + speeches[0])`），可见 `extract_play.py` 的实现属于缺陷而非既定体例；《项目说明》备注亦明确「舞台说明为整段正文或行内 `*（动作）*`」，即整段舞台说明本应在交付范围内。

## 七、等级判定理由

- **等级：`D 严重`（并标注「挂起·待修」）**
- 对应判据：`D 严重` = 「成片漏译／整节无译文等结构性缺陷」。本书命中 **164 段成片缺失（占剧本正文英文词 14.5%、归一化字符 15.2%）**，且每幕收场说明与全部人物出场/动作说明尽失，属典型的成片漏译。
- 按模板 **B-2 定级口径** §3：「素材残缺根因在抽取环节、非译者失误，但交付物确实缺内容 → 报告写『挂起·待修』并给 D 严重（结构性缺陷），不要按 B/C 处理」。本项同时满足 B-2 的取证要求（给了字符比、起止位置百分比、未译词数占比、修复点与复算命令），故按 B-2 落 D，而未按 B-2 §2 的「前缀连续子串」形态处理（实测**不是**尾截断，是弥散式整类丢失，严重度不低于截断）。
- **必须与「译文质量」区分开**：单看译文本身，块内零漏译、英文对照块词级零损坏、术语与专名跨幕零漂移、数字全对、无夹带、结构契约全满足，**若仅评译文本应落 B 良好**（扣分项为 5 处 B 级 + 14 处 C 级）。但 `质量等级` 字段按交付物完整性取严，取 D。因此本报告不构成「译文不合格」的结论，而是「**交付物不完整、须重抽补译后重审**」。
- 未按 A 级记的原因：A 级的形态（块内整段漏译、块内章末截断、语义错配）在已保留内容中一处未见；成片漏译全部集中在素材层，模板指定该类归 D。
