# 质量校验与 EPUB 打包

把一本已译完的书做**质量校验 → 修复 → 合并 → 打包成双语 EPUB**。这是翻译流程的下游环节：译稿已经在 `译文/` 目录里（分章的 `.zh-CN.md`），本流程把它们汇成一本可阅读的双语 EPUB，并在打包前用脚本 + 人工核查把质量问题拦下来。

> 本流程**不重新翻译**，只校验与修复格式/漏译/错配/术语问题；遇到确属译文质量低劣的篇章，记入报告退回重译，不在本流程内重译。

---

## 角色与工作方式

你是一名双语出版物的**终校与排版**。读到本文件后：

1. 先读本文件全部，掌握三脚本契约与修复边界。
2. 读取目标项目的 `项目说明.md`（领域 / 形态 / 术语表位置）、`术语表.md`（硬约束）。
3. 按「执行步骤」推进：逐章校验 → 全书聚合校验 → 合并 → 打包 → 交付报告。

脚本一律用 **`python`** 调用（本机 `python3` 不存在），工作目录是仓库根。

---

## 输入

一个**已译完或部分译完**的项目目录 `翻译项目/<项目名>/`，至少包含：

```
翻译项目/<项目名>/
  项目说明.md
  术语表.md            ← 校验术语一致性的权威
  原文/*.md            ← 每章原文（校验覆盖率的对照源）
  译文/*.zh-CN.md      ← 每章译文（本流程的校验+打包对象）
```

「部分译完」也接受——只处理 `译文/` 里实际存在的 `.zh-CN.md`，并在报告里列出缺译章节。

---

## 三脚本契约（必须先理解）

本仓库的三个 Python 脚本是本流程的自动校验主力，**退出码非零即卡点**。理解它们各自查什么、查不到什么，才能正确判读结果。

### `scripts/check_bilingual.py <译文.zh-CN.md>` — 结构契约 + 错配筛查

查两件事：

1. **结构契约**（退出码层面硬约束）：
   - 块标记 `===Original===` / `===Chinese===` 是否**成对**（不连续同标记）。
   - 标题行（`#`/`##`…）是否都含 `/`（即「英文 / 中文」合并格式），无 `/` 视为未合并，警告。
2. **语义错配启发式筛查**（报告项，非硬约束）：
   - 取原文块里出现的显著数字（≥2 位，排除 2024/2025/2026），看紧跟的译文块里有没有这些数字。
   - 没有就报「可疑错配」——可能是译文配错了原文，也可能是译者把数字改写成了中文（如 18→十八），**有噪声，必须人工判断**。

**查不到**：纯漏译（某段原文整段没译，但已译部分标记仍成对）、术语不一致、译文质量/流畅度。这些靠 `check_coverage.py` 和人工补。

### `scripts/check_coverage.py <原文.md> <译文.zh-CN.md>` — 漏译检测

查**覆盖完整性**：把原文按空行切段，对每个原文段，在译文的 `===Original===` 块集合里算覆盖率（20-gram 命中率，阈值 0.55）。低于阈值报「可疑漏译段」。

- 原理：译文里的 `===Original===` 块应当复现了原文每一段。某段原文在译文 Original 块里找不到对应 → 可能整段被跳过。
- **查不到**：译文块存在但 Chinese 块空着、或 Chinese 块是另一段内容的错配。结构对但内容错的，靠人工抽读。

### `scripts/bilingual_to_epub.py <输入.md> <输出.epub> [--title 标题] [--author 作者]` — 打包

把**单个**双语 md 转成 EPUB3：`===Original===` 块原样输出（无背景），`===Chinese===` 块包进淡黄色背景 div，标题作游离内容不进块。**依赖 pandoc**（命令行）。

- 输入是**单文件**——所以打包前必须先把分章译文**合并成全书一个 md**（见执行步骤 4）。
- 打包只看标记格式，不校验内容；内容质量靠前面两步把关。

## 执行步骤

### 1. 盘点与排序

`ls 译文/*.zh-CN.md`，按章节自然顺序排列（参照 `translation_queue.csv` 的 file 列顺序，或文件名里的章节号）。记录：实际有多少章译文、`原文/` 里对应多少章、缺哪些。

### 2. 逐章自动校验（每章两脚本都跑）

对每个 `译文/<章>.zh-CN.md`：

```
python scripts/check_bilingual.py 译文/<章>.zh-CN.md
python scripts/check_coverage.py 原文/<章>.md 译文/<章>.zh-CN.md
```

把每章的退出码、可疑错配数、可疑漏译段数记进**章级问题清单**。退出码非零不是立即停——先把全书扫完，再统一处理，效率更高。

### 3. 逐章修复（分两类，边界要清楚）

#### 3a. 格式/结构问题（直接修，属本流程职责）

这些是脚本能确定性判定的，直接改 `.zh-CN.md`：

| 问题 | 表现 | 修法 |
|------|------|------|
| 标记不成对 | 连续两个 `===Original===` 或两个 `===Chinese===` | 检查该处是否漏了配对标记，补上缺失的 `===Chinese===` 或 `===Original===` |
| 标题未合并 | 标题行无 `/`（只有英文或只有中文） | 合成「英文 / 中文」一行 |
| 标记写法错 | `=== Original ===`（带空格）、`---Chinese---`（用减号）、行内标记 | 改成规范 `===Original===` / `===Chinese===` 独占一行 |
| 编码错 | 脚本报 UnicodeDecodeError | 用 `python -c "open(p,encoding='utf-8').read()"` 定位，以 UTF-8 无 BOM 重写 |

修完**重跑**该章两脚本，确认退出码归零或仅剩「数字锚点误报」。

#### 3b. 内容问题（人工核查，不擅自重译）

脚本报的「可疑错配」「可疑漏译」多为噪声，**逐条人工判断**：

- **可疑错配**：打开该处，读原文块和紧跟的 Chinese 块，确认语义是否对应。多数是译者把数字改成中文写法（如 32→三十二、$50,000,000→五千万）导致的误报——语义对就标注「误报，已核」，不改。真错配（英文讲 A、中文讲 B）才需调整 Chinese 块位置或内容。
- **可疑漏译**：定位原文段，在译文里搜其首句，确认是否真的缺失。真缺则从原文补译该段（这是允许的最小范围翻译，仅限补漏，不改写已有译文）；原文段只是被并入了相邻块的，标注「已并入邻块」即可。

术语一致性（`术语表.md` 里的词全文是否统一译法）：脚本不查，靠人工抽读——在合并后的全书 md 里搜几个关键术语词，看是否多处译法不一。发现不一致**统一成术语表的译法**（这是格式层修复，不算重译）。

> 修复边界：本流程只做**格式规整 + 补漏译 + 统术语**。若某章译文明显质量低劣（机翻腔、大段语义错误），**不要在本流程里重译**——记进报告，标「建议重译」，留给翻译流程。

### 4. 合并全书

确认每章都通过校验（退出码 0 或仅余已核误报）后，按章节顺序合并成**一个全书 md**：

```
python -c "
from pathlib import Path
order = [...章文件名按序...]
out = []
for fn in order:
    out.append(Path('译文', fn).read_text(encoding='utf-8').rstrip())
    out.append('')   # 章间空行
Path('译文', '<书名>.all.zh-CN.md').write_text('\n'.join(out), encoding='utf-8')
print('合并完成')
"
```

合并后对**全书文件**再跑一次 `check_bilingual.py`（不跑 coverage，全书拼接后段落对齐会乱，coverage 只在章级有意义）。通过后进下一步。

### 5. 打包 EPUB

先确认 pandoc 可用（`pandoc --version`）。**pandoc 缺失是硬阻塞**——`bilingual_to_epub.py` 调它生成 EPUB3，没装就打包不了。若缺失：

- 提示用户安装 pandoc（`winget install pandoc` / `choco install pandoc` / 官网下载），装完再继续；
- 不要尝试用别的方式绕过（脚本写死了 pandoc 调用）。

书名 / 作者从 `项目说明.md` 取（内容简述里有书名和作者）。打包：

```
python scripts/bilingual_to_epub.py 译文/<书名>.all.zh-CN.md <书名>.epub --title "中文书名" --author "作者"
```

EPUB 产物放仓库根目录或项目目录下（看用户指定；默认放项目目录）。

### 6. 验证 EPUB

```
python -c "
import zipfile, sys
p = '<书名>.epub'
z = zipfile.ZipFile(p)
bad = z.testzip()
print('EPUB 完整性:', 'OK' if bad is None else f'损坏: {bad}')
print('文件数:', len(z.namelist()))
print('含 mimetype:', 'mimetype' in z.namelist())
print('含 CSS:', any('css' in n for n in z.namelist()))
"
```

确认：zip 完整、含 mimetype、含注入的 CSS（译文淡黄背景靠它）。可选：用 EPUB 阅读器打开抽检一两章渲染。

### 7. 交付报告与总控同步

输出一份「终校与打包报告」，含：

- **校验汇总**：章数、每章 `check_bilingual` / `check_coverage` 结果（退出码、可疑项数）。
- **修复记录**：改了哪些格式问题、补了哪些漏译段、统一了哪些术语（逐条列位置）。
- **遗留问题**：标注「误报已核」的可疑项、建议重译的章节（若有）。
- **打包结果**：EPUB 路径、大小、完整性校验结果、书名/作者。
- **产物清单**：全书合并 md 路径、EPUB 路径。

把报告写入项目目录 `终校报告.md`。
打包完成后运行 `python scripts/refresh_progress.py`，自动将新打包书目同步汇入根目录 **`Plan.md`**「📦 EPUB 双语出版打包明细」与「📚 全生命周期主台账」。

## 边界与不做的事

- **不重译**已有译文，只补漏译段、统术语、修格式。质量低劣的篇章记报告退回。
- **不跑 `check_coverage.py` 于全书合并文件**——拼接后原文段与 Original 块的对应被打乱，结果不可信；coverage 只在章级跑。
- **不绕过 pandoc**。缺失就停下让用户装，不要用 markdown→HTML 手搓等替代方案。
- **不改原文** `原文/*.md`、不改 `术语表.md`（术语表是人工维护的权威，校验只读它，发现问题报告给人）。
- **不删除分章译文**。合并产物 `<书名>.all.zh-CN.md` 是新增文件，分章 `.zh-CN.md` 保留，便于后续单章修订。

## 常见问题判读速查

| 脚本输出 | 多数原因 | 处理 |
|---------|---------|------|
| `check_bilingual` 退出码 1 + 「可疑错配 N 处」，结构契约满足 | 译者把数字改成中文写法（32→三十二，`'98`→九八指 1898 年） | 逐条核语义，对就标误报，不改 |
| `check_bilingual` 退出码 1 + 标题无 `/` | 卷名页/题献页标题只有中文或只有英文 | 合成「英文 / 中文」 |
| `check_bilingual` 退出码 1 + 标题是纯罗马数字（`### III`） | 原文本身只有章号、无英文标题可合并 | **合法例外**：为与全书一致可写成 `### III / III`（章号既是原文也是"译文"），或直接保留纯章号并在报告注明例外 |
| `check_coverage` 报某段覆盖率低（且是短对话/单行） | 该段被并入相邻 Original 块（高频，如 `"Yes, sire."`、`*Avanti*`） | 搜首句在译文里定位；并入邻块则标「误报，已核」，真缺才补译 |
| `check_coverage` 报某段覆盖率低（长段落） | 可能真漏译，或该段被拆并入多个块 | 重点核查；真缺才补译 |
| `check_bilingual` 报「连续同标记」 | 漏了配对标记，或两块间夹了游离内容把块打断 | 看该处上下文补标记 |
| pandoc 报 `yaml_metadata_block` 相关 | 文件开头有形似 YAML 的 `---...---` | 脚本已默认关 yaml_metadata_block；若仍报，删文件开头的 YAML 头 |
| EPUB 里译文无黄底 | CSS 未注入或阅读器忽略背景 | 确认 zip 里含 css 文件；部分阅读器不支持 div 背景，属阅读器限制非产物问题 |

> 两条高频判读经验：① `check_coverage` 报**短对话行**覆盖率低，绝大多数是并入邻块的误报，不是漏译；② 标题是**纯罗马数字/阿拉伯数字章号**（原文无英文标题）触发「无 `/`」警告，属合法例外。
