# 领域配置：技术文档

本配置叠加于 `通用翻译引擎.md`，适用于软件文档、API 文档、系统提示词、操作手册等技术内容。读引擎掌握通用规则，读本文件掌握技术领域特有规则。

---

## 适用场景

- 软件/API/SDK 文档
- AI 模型的系统提示词（system prompts）
- 命令行工具说明、操作手册
- 包含代码示例的技术文章

---

## 保持原样清单（补充）

除通用引擎第四节外，技术文档中以下内容**保持原样不译**：

| 类型 | 示例 |
|------|------|
| 代码块内容 | 函数体、命令、配置（见下方「代码块处理」） |
| 命令行 | `npm install`, `git commit`, `rg --files` |
| 工具名 / API 名 | `web_search`, `file_search`, `str_replace` |
| 函数 / 变量 / 类名 | `searchMcpRegistry`, `function_call()`, `MyClass` |
| 文件路径 | `/home/user/skills/SKILL.md`, `src/index.ts` |
| 参数名 / 配置键名 | `description`, `old_str`, `temperature`, `max_tokens` |
| 命名空间 / 标识符 | `mcp__codex_apps__github` |
| 技术缩写 | API, MCP, CLI, TTS, JSON, HTTP, YAML, SDK, URL, SQL |
| 产品 / 软件名 | Linux, Docker, Kubernetes, PostgreSQL, Redis |
| 版本号 | v2.3.1, 4.8, 5.6 |

## 代码块处理

代码块（``` 围栏内的内容）整体保留结构，**仅翻译其中的注释和说明性字符串**：

- 代码逻辑、函数名、变量名、语法关键字：不译。
- 注释（`// 说明`, `# 说明`, `/* 说明 */`）：翻译其中的人类可读说明文字。
- 字符串字面量中面向用户的提示文案：翻译；纯标识符性质的字符串：不译。

示例：

源码：
```python
# This function searches the registry
def search_registry(query):
    return results
```

译后注释：
```python
# 该函数搜索注册表
def search_registry(query):
    return results
```

### JSON / YAML 工具定义

JSON/YAML 整体结构保留，**仅翻译 `description`、`title`、`label` 等可读字段的文字**。键名（key）和类型值（`string`/`number`/`boolean`）不译：

源：
```json
{
  "name": "web_search",
  "parameters": {
    "properties": {
      "query": {
        "description": "Search query string",
        "type": "string"
      }
    }
  }
}
```

译：
```json
{
  "name": "web_search",
  "parameters": {
    "properties": {
      "query": {
        "description": "搜索查询字符串",
        "type": "string"
      }
    }
  }
}
```

## 术语处理

- 使用业界通行的中文译法。例如 `database` 译「数据库」而非「资料库」，`token` 视语境译「令牌」或「词元」。
- 核心技术术语首次出现可用「中文（English）」标注，后续直接用中文。
- 若项目提供 `术语表.md`，严格遵守，优先级高于本配置的默认译法。

---

## 风格

- 简洁、直接。技术文档不追求文学性，追求准确和无歧义。
- 指令性内容用祈使句：原文 "Click the button" 译「点击按钮」，不译「你应该点击按钮」。
- 主动语态优于被动语态。
- 保留原文的强调语气：`must` 译「必须」，`should` 译「应当」，`may` 译「可以」。

---

## XML 标签

技术文档（尤其系统提示词与配置文件）常含自定义 XML 标签，如 `<system_behavior>`、`<product_information>`。标签本身不译，标签内的文字内容照常翻译。

---

## 输出粒度

**默认：块对照，数段合译**。

技术文档的段落常围绕同一指令或同一概念展开，逐段切开会打断上下文。默认允许把**连续的数个段落合并成一个 `===Original===` 块**、对应一个 `===Chinese===` 块，一次性翻译，使译文更连贯。

- **上限：每个块合计不超过 500 词**（约 2-6 段）。接近上限或遇标题、代码块边界时，应另起新块。
- **只在段落边界合并**：不在句子中间断开原文；标题、列表、代码块这些结构单元整体归属一个块，不跨单元拼接。
- **保持成对**：每个 `===Original===` 块后紧跟其 `===Chinese===`，译文覆盖该块全部原文，不漏不增。
- **不要无脑堆满**：合并的目的是连贯，不是凑数。一段一个意思就单独成块；逻辑紧密的数段才合并。

若「项目说明.md」指定逐段对照，则遵从其规定，每段独立成块。

## 翻译范围补充

以下技术文档常见元素都要翻译（不要因为「看起来像代码」就跳过）：

- 正文段落、标题（`# Tools` 译为 `# 工具`）
- 列表项、表格文字
- 示例对话中的文字
- 错误提示、UI 文案
