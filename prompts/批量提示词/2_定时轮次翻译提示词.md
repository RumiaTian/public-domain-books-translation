# 定时批量翻译提示词（子代理调度 · MCP 工具流 · 正本 v2）

> v2（2026-10-22）：新增 1301 内容拦截三防线（worker 跳书 / 调度会话记拦截清单重派 / batch_begin 自动排除）、整书收官自动清锁、超长段落句子级分块、转述带 token 用量。
> 原则依旧：提示词纯参数、零状态——书单与进度只认 CSV 与锁文件。
> 创建方式：**每条任务在单独的新对话中创建**（任务绑定创建会话，分开建 = 独立上下文）。
>
> | 任务 | cron | 批次 | 用哪版 |
> | :--- | :--- | :--- | :--- |
> | 01 翻译批次1 | `0 18 * * *` | 1 | 批次1 版 |
> | 02 翻译批次2 | `5 21 * * *` | 2 | 批次2 版 |
> | 03 翻译批次3 | `10 2 * * *` | 1 | 批次1 版 |
> | 04 翻译批次4 | `15 10 * * *` | 2 | 批次2 版 |
>
> 映射说明：四窗口 = 批次 1/2/1/2（批次3 书池暂闲置，复活只需把某条任务换成批次3 版）。

## 批次1 版（01 / 03）

```text
翻译调度会话（批次1）。工作目录 C:\Users\HanTi\Desktop\translate。当你收到这句话，说明额度已经恢复，大力开跑！

把本次窗口的全部工作派给一个子代理执行（Agent 工具，类型 general-purpose，前台等待），指令原文如下：

你是翻译执行 worker（批次1）。工作目录 C:\Users\HanTi\Desktop\translate。本指令即全部流程，翻译上下文由 MCP 工具按需返回。
1. 调用 mcp__translate-mcp__batch_begin，参数 batch_id=1：先处理重试队列（整章重投/断点续译），再按候选书单取书（内容拦截回避书目已自动排除）。
2. 每章循环：
   - mcp__translate-mcp__claim_task(project=书名)：认领首个 todo 章节；返回"被外部锁持有"则换候选单下一本。
   - mcp__translate-mcp__context_pack(project, file)：取本章术语命中、领域摘要、黄金样本、前章衔接。
   - mcp__translate-mcp__get_blocks(project, file)：取原文分块，只译标注待译的块。
   - 主模型直译：术语按命中定名，保持数字锚点，带标题的块附 title_zh。
   - mcp__translate-mcp__submit_translation(project, file, blocks)：PASS 进下一章；PARTIAL 补齐剩余块后重交；FAIL 按返回的违规行修复后重交（幂等）；同一章 3 次未过即跳过，换下一篇。
   - 本书 todo 清零后回候选单换下一本（认领锁已自动清除）。
3. 停止规则：额度耗尽 → 停止开新章，进入第 4 步（已交章节均已落盘）；某本书触发内容拦截（1301 / 敏感内容报错）→ 跳过该书换下一本，在总结中列出书名；连续 3 本书失败 → 停止进入第 4 步。
4. 收尾：python scripts/refresh_progress.py → git add -A && git commit -m "sync: 批次1 MCP 自动翻译" → git -c http.proxy=http://127.0.0.1:7890 push；git 某步失败一次即止。
5. 最后返回一行总结：完成/断点/跳过各几章、当前书与章、内容拦截书名、git 结果。

子代理返回后，把总结连同它的 token 用量（结果里的 subagent_tokens）一并转述，本次窗口即结束。

若子代理异常死亡（返回报错而非总结）：运行 tail -1 mcp/活动日志.txt 找到卡住的书 → 把书名追加到 mcp/拦截清单.txt（一行一个）→ 用上面同样的 worker 指令重派一次子代理 → 再失败则本次窗口直接结束。追加后无需其他善后，下个窗口自动绕开该书。
```
