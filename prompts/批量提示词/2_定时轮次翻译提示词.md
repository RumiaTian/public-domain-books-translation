## 批次1 版（01 / 03）

```text
翻译调度会话（批次1）。工作目录 C:\Users\HanTi\Desktop\translate。当你收到这句话，说明额度已经恢复，大力开跑！

并发派 2 个子代理（Agent 工具，类型 general-purpose，run_in_background: true），给每个子代理相同的下述指令原文。并发安全由 claim 锁与跨进程写锁保证，两者会各自认领不同的书：

你是翻译执行 worker（批次1）。工作目录 C:\Users\HanTi\Desktop\translate。本指令即全部流程，翻译上下文由 MCP 工具按需返回。
1. 调用 mcp__translate-mcp__batch_begin，参数 batch_id=1：先处理重试队列（整章重投/断点续译），再按候选书单取书（内容拦截回避书目已自动排除）。可能存在并行 worker：认领被拒（外部锁/无 todo）就换下一本。
2. 每章循环：
   - mcp__translate-mcp__claim_task(project=书名)：认领首个 todo 章节。
   - mcp__translate-mcp__context_pack(project, file)：取本章术语命中、领域摘要、黄金样本、前章衔接。
   - mcp__translate-mcp__get_blocks(project, file)：取原文分块，只译标注待译的块。
   - 主模型直译：术语按命中定名，保持数字锚点，带标题的块附 title_zh。
   - mcp__translate-mcp__submit_translation(project, file, blocks)：PASS 进下一章；PARTIAL 补齐剩余块后重交；FAIL 按返回的违规行修复后重交（幂等）；同一章 3 次未过即跳过，换下一篇。
   - 本书 todo 清零后立即回候选单开下一本，再译完再开下一本，永不停歇。
3. 运行纪律（最重要）：本窗口唯一目标是持续翻译、直到系统终止你的回合。额度耗尽/内容拦截会由系统直接杀死回合，不需要也不允许你自行判断"该收尾了"——禁止因"完成了一本书""运行时间较长""完成了一定章数"而返回。仅两种情况允许自主返回：① 候选与重试队列均空（总结注明"书池已空"）；② 上下文明显过重（总结注明"容量收尾需重派"）。1301/内容拦截类报错：跳过该书、记下书名、继续下一本。
4. 收尾 git 与 refresh 由调度会话统一执行：你不要运行任何 git 命令，也不要运行 refresh_progress.py。
5. 最后返回一行总结：完成/断点/跳过各几章、当前书与章、内容拦截书名、停止原因（书池已空/容量收尾/系统终止）。

槽位管理（调度会话职责）：
- 收到子代理完成通知后检查其总结：停止原因不是"书池已空/容量收尾/系统终止"（提前收尾）→ 立即按原指令重派一个新子代理补位；始终保持并发度 2，直到两个槽位都出现合法停止原因。
- 总结为"容量收尾需重派"时：从总结中取当前书名，先运行 rm "翻译项目/<书名>/认领.md" 删除该书认领锁，再重派——让新 worker 立即接管同一本书的断点（否则活跃锁会拦它 4 小时）。
- 子代理异常死亡（报错而非总结）：先看报错类型——额度类（429/额度不足/quota/insufficient）→ 不拉黑任何书，直接结束本窗口（额度约 5 小时后重置，下个窗口自动续跑）；内容拦截类（1301/敏感内容）→ 优先从报错文本找书名，找不到则运行 tail -1 mcp/活动日志.txt 取最近的书 → 把书名追加到 mcp/拦截清单.txt（一行一个）→ 立即重派补位；累计拉黑 3 本书才关闭该槽位。
- 两个槽位都合法停止后统一收尾：git add 翻译项目 mcp && git commit -m "sync: 批次1 MCP 自动翻译" → git -c http.proxy=http://127.0.0.1:7890 pull --rebase -X ours origin main → git -c http.proxy=http://127.0.0.1:7890 push；git 某步失败一次即止。根看板（Plan.md/README/根CSV）是派生文件，由 Mac 端独占刷新——不运行 refresh_progress.py，不 add 仓库根目录的任何文件，保持工作区干净。
- 最后把两个子代理的总结连同各自 token 用量（subagent_tokens）一并转述。
```
